## 3. 方式 B：mysql 命令行客户端（标准方式）

你本机的 MySQL 是「服务在跑、但 `mysql.exe` 不在常规目录」的形态（探测 `C:\Program Files\MySQL` 等常见路径均不存在）。要用命令行客户端，先**找到 `mysql.exe`**：

- 用 Everything / _listary_ 搜 `mysql.exe`；
- 或在「服务」里双击 MySQL 服务，看「可执行文件路径」推断安装目录（一般在同目录的 `bin\` 下）。

找到后，在终端执行（注意把路径换成你实际的）：
```bash
"你的路径\mysql.exe" -h 127.0.0.1 -P 3306 -u root -p < 01_init.sql
```
输入密码 `123456` 回车即可。脚本会一次性建库 + 建表 + 插字典。

> 若提示「mysql 不是内部或外部命令」，说明没用绝对路径；或把 `mysql.exe` 所在目录加进系统 PATH 后重开终端。

## 6. 本次设计修正记录（已同步到脚本与设计文档）

| 位置 | 原定义 | 修正后 | 原因 |
| --- | --- | --- | --- |
| `dict_injury_level.level_code` | `CHAR(2)` | `CHAR(3)` | 分级代码 `III` 为 3 字符，`CHAR(2)` 插不进，报 `Data too long` |
| `adverse_event.injury_level` | `CHAR(2)` | `CHAR(3)` | 外键须与主键同类型，随上同步加宽 |
| `数据库设计.md` 对应字段表 | `CHAR(2)` | `CHAR(3)` | 保持「设计文档 = 脚本」逐列一致 |

> 该不一致在校验建库时被实测抓出并修复，证明「按设计文档实际跑一遍」的必要。

## 8. 常见问题（FAQ）

| 现象 | 原因 / 解决 |
| --- | --- |
| `Access denied for user 'root'@'localhost'` | 用的是 `localhost`（socket）而非 `127.0.0.1`（TCP）。本机 root 仅 `127.0.0.1` 可连，连接串写 `127.0.0.1`；密码是 `123456` |
| `Can't connect ... 3306` | MySQL 服务没启动，见第 1 节 `net start mysql80` |
| `table already exists` | 库已存在。用方式 A 的 `--rebuild`，或图形化里先删 `nursing_ae_db` 再跑脚本 |
| `Data too long for column 'level_code'` | 旧 `CHAR(2)` 缺陷，已修复为 `CHAR(3)`，请用最新 `01_init.sql` |
| 中文乱码 | 库/表/连接都要 `utf8mb4`；连接串已带 `characterEncoding=utf8mb4` |
