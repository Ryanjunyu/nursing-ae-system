1. 设计目的

针对护理不良事件上报流程繁琐、上报意愿低、缺少电子化根因分析辅助工具的业务现状，本课程设计旨在实现一个“住院护理不良事件上报与根因辅助分析原型系统”。通过该系统的分析与构建，达成以下教学目的：

  • 掌握医疗事件类信息系统的需求建模方法（角色、用例、业务流程、数据建模）；
  • 理解并实践权限系统设计：基于角色的访问控制（RBAC）与数据范围隔离，落实分级权限；
  • 掌握结构化表单开发：必填校验、关键字段约束、匿名上报选项；
  • 完成多维度统计分析：按科室、类型、损伤等级、时间区间聚合，输出可视化图表定位高频安全问题；
  • 理解 RCA 根本原因分析（Root Cause Analysis） 在医疗安全中的应用，体会医疗安全管理业务；
  • 强化医疗隐私保护与分级权限控制的工程实践能力。

2. 课题背景

2.1 护理不良事件与上报现状痛点

护理不良事件包含跌倒、压疮、输液外渗、坠床等。传统纸质上报流程复杂、填写项多，事后汇总统计工作量巨大。据行业调研，当前医疗安全管理普遍面临以下痛点：

  • 上报率低、耗时长：纸质或复杂电子表单让一线护士“报一次十几分钟”，挤压临床时间，导致主动上报意愿低；
  • 匿名保障不足：纸质记录或权限痕迹可能暴露上报者身份，抑制“非惩罚性”上报文化，形成“沉默螺旋”；
  • 分析辅助工具缺失：手工绘制鱼骨图缺乏多维度数据支撑，常将复杂事件简单归咎于个人操作失误，忽视流程、设备、环境等系统性因素；
  • 闭环断裂：“分析—改进”传导链断裂，整改措施常停留在纸面，同类隐患反复发生。
设计切入点：用“移动端/Web 轻量填报 + 匿名通道 + 内置 RCA 五维模板 + 自动统计”破解上述痛点，把上报成本降到最低、把根因分析变成结构化引导。

2.2 根因分析（RCA）在医疗安全中的应用

RCA 起源于“瑞士乳酪理论”，是一种基于团体、系统、回顾性的不良事件分析方法。其核心不是追责个人，而是找出系统/流程中的风险与漏洞，从源头改进，预防同类事件再次发生。RCA 关注 5W1H：发生了什么（What）、在谁身上（Who）、何时（When）、何地（Where）、为何发生（Why）、如何杜绝（How）。

2.3 隐私保护与分级权限的工程意义

患者安全事件涉及敏感个人信息。国家卫生健康委要求落实电子病历信息分级分类访问控制与权限管理，遵循“最小可用原则”，严禁未经授权查阅、复制、传播。本原型将“患者信息脱敏展示 + 分级数据范围隔离 + 全操作审计留痕”作为安全基线，使学员在原型开发中建立合规意识。

3. 相关资料调研综述

3.1 护理不良事件定义与分类

国内普遍认为：护理不良事件是在护理过程中发生的、非计划内、未预计到的事件，包括住院期间发生的跌倒、坠床、给药错误、输液/输血意外、管路滑脱、走失、误吸、烫伤等。按事件性质，常用分类（共 10 大类）如下：

大类典型事件与本题关联
1 不良治疗给药错误、输血错误、输液/输血反应输液外渗属静脉治疗相关
2 意外事件跌倒、坠床、走失、烫伤本题核心：跌倒、坠床
3 护患沟通事件护患争吵、暴力行为—
4 饮食/皮肤护理误吸/窒息、院内压疮本题核心：压疮
5 辅助诊查/转运身份识别错误、标本丢失—
6 管道护理管道滑脱、自行拔管—
7 职业暴露针刺伤、割伤—
8 公共设施设施故障、有害物质泄漏—
9 医疗设备器械仪器故障、器械不达标RCA“机”维度
10 供应不良消毒不达标、器械包不符—

3.2 损伤分级标准（中国医院协会四级）

国内普遍采用中国医院协会标准，按事件严重程度由轻至重分为 4 级，本原型的“损伤分级字典表”即依此建模：

级别名称定义
Ⅰ级警告事件非预期的死亡，或非疾病自然进展造成永久性功能丧失
Ⅱ级不良后果事件诊疗活动中因诊疗（非疾病本身）造成患者机体与功能损害
Ⅲ级未造成后果事件发生错误事实，但未造成机体与功能损害
Ⅳ级隐患事件及时发现错误、未形成事实（近似错误 / Near-miss）
教学要点：Ⅳ级“隐患事件/近似错误”是上报意愿最低但价值最高的数据，原型通过“匿名 + 低门槛”专门鼓励此类上报。

3.3 RCA 方法论：人-机-料-法-环

RCA 从“人、机、料、法、环”五维度（部分扩展为六维加“测”）分析事故诱因，并辅以鱼骨图与时间序列表。本原型将五维度做成结构化填报模板，引导填写人员记录事件各类诱因，沉淀根因分析记录。

维度含义护理场景示例
人人员因素低年资护士风险认知不足、查对制度落实不到位
机设备因素输液泵无渗漏预警、无血管可视化辅助设备
料物料因素高渗药物（如 10% 葡萄糖酸钙）、穿刺静脉管径细小
法方法/制度标准化流程缺失、交接班制度执行不严
环环境因素夜间照明不足、地面湿滑、病区布局不合理

3.4 电子化上报与匿名上报机制

WHO 患者安全建议：上报系统应匿名、易用、全员可访问、基于非惩罚文化。研究表明，匿名保障缺失是抑制上报意愿的关键因素之一；而电子平台支持实时类型/时间/地点/人员/情境分析，能显著提升患者安全指标（如降低跌倒率、减少用药错误）。本原型据此设置“匿名上报”开关：勾选后系统不绑定上报人身份，审计日志以“ANONYMOUS”记录，杜绝身份追溯。

3.5 隐私保护与分级权限合规要求

  • 去辨識原则：姓名、身份证号、电话、地址、病历号、床号等可辨识信息，以代号替代或脱敏，至无法推测原始信息；
  • 分级权限：按角色与岗位设置分级访问权限，遵循“最小可用原则”；
  • 全链路留痕：填报、查看、修改、删除、导出等操作记录审计日志，实现可追溯、不可篡改。

4. 需求分析

4.1 业务角色与流程

系统三类角色：普通护士 NURSE科室护士长 HEAD_NURSE系统管理员 ADMIN。核心业务流程：

事件发生 → 护士填报（可匿名）→ 系统必填校验 → 写入主表+审计 → 护士长/管理员查看（按范围隔离）→ 触发 RCA 分析（五维模板）→ 生成改进措施 → 统计分析/图表 → 闭环

4.2 功能需求列表

编号功能模块关键需求
F1用户权限管理三角色；数据访问范围隔离；支持匿名上报选项
F2不良事件填报表单事件时间/科室/类型/损伤等级/经过/现场；必填校验
F3RCA 根因辅助分析人-机-料-法-环 五维模板；时间序列表；保存分析记录
F4事件检索筛选按科室/类型/损伤等级/时间区间筛选；护士长仅本科室，管理员全部
F5统计分析各科室各类事件数量；图表定位高频安全问题
F6安全约束患者信息脱敏；全操作审计日志

4.3 非功能需求

  • 隐私合规：患者姓名/证件号脱敏存储与展示；敏感字段在审计参数中脱敏；
  • 权限正确：越权访问必须被拒绝并返回无权限提示；
  • 易用性：填报核心信息 3 分钟内可完成，支持匿名；
  • 性能：原型数据量小，统计查询响应 < 1s；
  • 教学模拟：全部为模拟数据，界面显著标注“教学模拟，不用于临床”。

6. 技术方案

6.1 总体架构

采用前后端分离的 B/S 架构：

层职责
表现层Vue3 + Element Plus 单页应用：填报、检索、RCA 表单、统计图表
控制层Spring Boot Controller：RESTful API、JWT 鉴权、参数校验
业务/安全层Service + Spring Security：权限判定、数据范围隔离、匿名脱敏、AOP 审计
持久层MyBatis-Plus：表映射、分页、条件构造
存储层MySQL 8.0：9 张表

6.2 技术栈选型

维度选型理由
前端Vue3 + Vite + Element Plus + Pinia + Axios组件化表单、易做必填校验与脱敏展示
图表ECharts各科室/类型柱状图、损伤等级饼图、时间趋势折线
后端Spring Boot 3 + MyBatis-Plus贴合课程 Java 技术栈，便于权限/审计实践
安全Spring Security + JWT无状态鉴权、角色与数据范围控制
数据库MySQL 8.0成熟稳定，支持外键/索引
审计Spring AOP / 拦截器统一记录操作日志
备选方案：若追求极简部署，可降为 Flask + SQLite + 原生前端；若仅做界面原型，可用纯前端 + Mock 数据。本计划书以 Spring Boot + Vue3 为主推方案，工程实践价值最高。

6.3 权限与安全设计

  • RBAC 角色：NURSE / HEAD_NURSE / ADMIN，权限码控制菜单与接口；
  • 数据范围隔离：查询自动叠加部门条件——护士仅本人提交及本科室脱敏列表；护士长仅本科室全部；管理员全部；
  • 匿名上报：前端勾选“匿名”→ 后端 reporter_id=NULL，审计以 ANONYMOUS 记录，无任何身份关联；
  • 脱敏展示：患者姓名/证件号/住院号脱敏存储与列表脱敏；明细页按角色授权展示；
  • 审计全留痕：AOP 拦截填报/查看/修改/删除/导出，写入 sys_audit_log，敏感参数脱敏。

6.4 RCA 辅助分析实现

RCA 模块以“五维模板 + 时间序列表 + 鱼骨图”实现辅助分析：

  • 表单：人/机/料/法/环 五个文本域，引导填写近端原因与根本原因；
  • 时间序列表：按时间轴还原事件经过（结构化输入）；
  • 鱼骨图：基于五维数据用 ECharts 渲染可视化，辅助汇报；
  • 保存：写入 event_factor（诱因）与 rca_record（根因+改进措施），状态机 NOT_STARTED→ANALYZING→DONE。

6.5 统计分析图表方案

图表维度用途
柱状图各科室 × 各事件类型 数量定位高频安全问题与薄弱科室
饼图损伤等级分布（Ⅰ-Ⅳ）评估严重程度构成
折线图按月的事件趋势观察改进前后变化
词云/列表高频诱因关键词辅助 RCA 方向

7. 业务功能模块详细设计

7.1 用户权限管理

  • 三角色数据访问范围：护士（本人+本科室脱敏）、护士长（本科室全部）、管理员（全部+用户管理）；
  • 登录鉴权（JWT），密码加密；支持“匿名上报”选项，不改变登录态但上报时不绑定身份。

7.2 不良事件填报表单

  • 字段：事件发生时间、科室、事件类型、损伤等级、事件经过、现场情况；
  • 必填校验：上述关键字段不能为空；时间不晚于当前；类型/等级下拉取自字典表；
  • 提交即写主表 + 审计日志；可选匿名。

7.3 RCA 根因辅助分析模块

  • 提供“人-机-料-法-环”五维填报模板；
  • 引导记录事件各类诱因，保存至 event_factor 与 rca_record；
  • 生成时间序列表与鱼骨图，输出改进措施。

7.4 事件检索筛选

  • 按科室、事件类型、损伤等级、时间区间组合筛选；
  • 护士长仅可查看本科室事件；管理员查看全部；列表展示脱敏患者信息。

7.5 统计分析功能

  • 统计各科室各类不良事件发生数量；
  • 输出柱状/饼/折线等图表，定位高频安全问题，支持导出统计结果。

7.6 安全约束

  • 患者信息脱敏展示（姓名/证件号/住院号）；
  • 所有填报、查看、修改、删除、导出操作记录审计日志。

  • 验证匿名事件在列表中不暴露上报人。
