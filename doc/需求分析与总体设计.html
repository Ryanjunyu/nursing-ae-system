1. 需求分析

1.1 业务角色与用例

系统面向三类角色，权限与数据访问范围严格隔离：普通护士 NURSE科室护士长 HEAD_NURSE系统管理员 ADMIN。下图为用例图，刻画各角色可执行的系统功能。

1.2 功能需求列表

编号功能模块关键需求主要角色
F1用户权限管理三角色；数据访问范围隔离；支持匿名上报选项ADMIN / 全体
F2不良事件填报表单事件时间/科室/类型/损伤等级/经过/现场；必填校验NURSE

F5统计分析各科室各类事件数量；图表定位高频安全问题HEAD_NURSE / ADMIN

1.3 非功能需求

  • 隐私合规：患者姓名/证件号脱敏存储与展示；敏感字段在审计参数中脱敏；
  • 权限正确：越权访问必须被拒绝并返回无权限提示；
  • 易用性：填报核心信息 3 分钟内可完成，支持匿名；
  • 性能：原型数据量小，统计查询响应 < 1s；
  • 教学模拟：全部为模拟数据，界面显著标注"教学模拟，不用于临床"。

4. 总体方案

4.1 技术架构

图 4-1 总体技术架构图（五层 + 横切安全审计）

4.2 技术栈选型

维度选型理由
前端Vue3 + Vite + Element Plus + Pinia + Axios组件化表单、易做必填校验与脱敏展示
图表ECharts各科室/类型柱状图、损伤等级饼图、时间趋势折线
后端Spring Boot 3 + MyBatis-Plus贴合课程 Java 技术栈，便于权限/审计实践
安全Spring Security + JWT无状态鉴权、角色与数据范围控制
数据库MySQL 8.0成熟稳定，支持外键/索引
审计Spring AOP / 拦截器统一记录操作日志
备选方案：若追求极简部署，可降为 Flask + SQLite + 原生前端；若仅做界面原型，可用纯前端 + Mock 数据。本方案以 Spring Boot + Vue3 为主推，工程实践价值最高。

4.3 权限与安全设计

  • RBAC 角色：NURSE / HEAD_NURSE / ADMIN，权限码控制菜单与接口；
  • 数据范围隔离：查询自动叠加部门条件——护士仅本人提交及本科室脱敏列表；护士长仅本科室全部；管理员全部；
  • 匿名上报：前端勾选"匿名"→ 后端 reporter_id=NULL，审计以 ANONYMOUS 记录，无任何身份关联；
  • 脱敏展示：患者姓名/证件号/住院号脱敏存储与列表脱敏；明细页按角色授权展示；
  • 审计全留痕：AOP 拦截填报/查看/修改/删除/导出，写入 sys_audit_log，敏感参数脱敏。

4.4 RCA 辅助分析与统计方案

  • RCA 实现：人/机/料/法/环 五维文本域 + 时间序列表 + ECharts 鱼骨图；状态机 NOT_STARTED→ANALYZING→DONE；数据写入 event_factor 与 rca_record。
  • 统计图表：柱状图（科室×类型）、饼图（损伤等级分布）、折线图（月度趋势）、词云（高频诱因），定位高频安全问题并支持导出。
